## 为什么是旅游宝

「旅游宝」的能力不设话题边界——生活里的事都能问；在旅行场景（路线、玩法、吃饭、交通、天气）上是看家本领。目标不是做"更聪明的行程规划器"，而是做**途中决策的接管器**：系统被动感知你的体力与情境，在你开口之前给出一个可以立刻执行的动作，**你只保留否决权**。

| 设计原则 | 一句话解释 |
|---|---|
| 🚫 零决策 | 不给你一堆选项让你挑，只给一个能立刻照做的动作 |
| 🔢 带数字 | 时间、距离、价格、班次——没有数字的建议不算建议 |
| 🗣️ 语音优先 | 按住说话、松手即问、回答自动朗读，路上不用打字 |
| 💰 免费优先 | 大模型、语音识别、朗读、离线地图全部有免费开源方案 |

## 🚀 快速开始

```bash
git clone https://github.com/jingrongx/66.git
# 用 Android Studio（Ladybug 以上）打开，或命令行构建：
./gradlew assembleDebug
```

首次启动配置：

1. 「设置」→ 选服务商（默认 DeepSeek）→ 填入 API Key → 测试连接 → 保存
2. 可选：填高德 Key 解锁附近搜索与步行路线；去「离线地图」下载所在省份；填「常用地址（家）」解锁一句话回家；家里有老人打开「大字模式」

- DeepSeek API Key 在 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 申请
- 高德 Key 在 [lbs.amap.com](https://lbs.amap.com) 申请（**Web 服务**类型）
- 所有 Key 只保存在本机 DataStore

## 🗺️ 路线图

- ⬜ **视频通话**（AI 真人般实时视频对话）：真正的全双工视频对话需要实时全模态大模型，按量计费与"能免费就免费"冲突；当前免费替代 = **语音通话 + 拍照提问**，已覆盖"边看边问"的主要场景
- ⬜ 公共信息飞轮（脱敏贡献公共池：需要用户明示授权 + 轻量后端）
- ⬜ 群体情境层（按同行结构/体力档位加权证据）+ 推荐多样性（探索意愿状态变量）
- ⬜ 足迹热力图与多日轨迹管理（当前只叠加最近轨迹）
- 🟡 端侧语音：唤醒词已离线（sherpa-onnx KWS，5.2MB 模型编进包）；端侧转写仍未做（云端 ASR 质量更好、包体省 40MB+）
- ⬜ 交通时刻表类硬信息的专项数据源接入

## 📜 更新日志

**v0.9.38** · 播报破音——两个真实的 bug 叠在一起。①**起播缓冲几乎是空的**：`SpeechSink.count()` 第一次写入就 `play()`，而 MediaCodec 一次只吐 85ms 左右的 PCM；Edge 的 WSS 推流又接近实时（实测 4 秒收 3 秒音频），供给速度刚好压在播放线上，网络稍一抖动立刻欠载——听感正是「某个字突然破了」。改成攒够 450ms 预滚才起播，短句写完再兜底 `ensureStarted()`（否则低于预滚量的句子会一直憋着不出声）；轨道缓冲同时从 96KB（2 秒）加厚到 192KB（4 秒）。②**流式喂帧会丢数据**：`val data = leftover ?: polled`——只要上一帧没喂完，刚从队列 poll 出来的新帧就再也没人用，MP3 字节流中间被挖掉一块，解出来同样是破音。改成把新帧接到 leftover 后面合并、EOS 先挂起等 leftover 喂完再发，一个字节都不丢。顺带加了两行诊断：`共用音轨起播：预滚 Xms`（太小=容易欠载，太大=首句变慢，调参看它）和「段格式与音轨不一致」告警。

**v0.9.37** · 空转惩罚改成「直接不送」——0.9.36 装到机器上十分钟就看出来了：直播人声那段的峰值是 **−8 dBFS**，而门槛只从 −46 dB 抬到 −40 dB，抬 6 dB 对它毫无作用，照样起振、照样往云端发。所以惩罚方式换成**整段丢弃**：连续两次空转后，90 秒内待机语音段直接删掉，连通写请求都不发（唤醒仍由端侧 KWS 兜着，喊「小源小源」照常秒回）。同时 KWS 一旦命中就立刻卸掉惩罚、恢复正常灵敏度——真有人在跟机器说话时，不该再装聋。日志里能看到 `空转惩罚中：跳过待机语音（已跳 N 段）`。

**v0.9.36** · 待机空转的三道闸——断连前那 50 秒日志里，待机误触发 13 次，全部「峰值 −10~−19 dBFS、信噪比 11~34 dB、转写为空」：都是直播里的人在说话，白跑一次云端转写、白占采集通道。根因是待机判据只看电平和信噪比，不看「这段到底像不像人话」。三道闸一起上：①**模型门槛从 0.2 抬到 0.45**——RNNoise 的语音概率以前只在起振那一下做个宽松否决，纯背景人声常常擦线过；现在待机档要连续 3 帧（240ms）都过 `standbyVadMin` 才算开口（「小源小源」四音节至少 600ms，不会漏），而播报中（barge-in）不吃这条——那一刻用户就是要打断，宁可松一点。RNNoise 不可用时自动放行，不会把耳朵堵死。②**空转惩罚**：连续两次「能过电平、云端却认不出字」，就把待机起振门槛临时抬 6 dB、静音 90 秒；一旦识别到正常文本立刻卸掉，不耽误真人喊话。会话重建（切前后台、改灵敏度）会把剩余的惩罚时长接着传下去，不会白罚。③**极短片段本地丢弃**：短于 550ms 的段子（叹气、咳嗽、「嗯」「啊」）不再发云端——「小源小源」四音节正常语速也有 700~1000ms，不会误伤。

**v0.9.34** · 真正能熄屏了——0.9.33 装上后发现「撤掉保持亮屏」根本没用：`mStayOn` 已经是 false、超时也设了 30 秒，屏幕照样常亮。翻系统日志才看清这台机器人的固件改过 `PowerManagerService`：到点不执行睡眠，而是打一行 `hhk  System idle time out!,and sendBroadcast to app!`，每 30 秒发一次 `com.android.server.ACTION_TRIGGER_IDLE`，把「睡不睡」交给应用决定；**把应用 force-stop 之后屏幕依然常亮**，所以不是我们占着屏幕。`PowerManager.goToSleep()` 要 `DEVICE_POWER`（系统签名），普通应用拿不到，唯一不需要系统签名的正规路子是 `DevicePolicyManager.lockNow()`。于是补了一条完整链路：`ScreenAdminReceiver` 只申请 `<force-lock/>` 一项设备管理器权限（不碰数据、密码、相机），空闲到点时先试系统 `goToSleep`（预置到 priv-app/系统签名的版本会自动走这条），没有权限就退到 `lockNow()`；两条都不通时记一行日志说明原因。设置页新增「熄屏权限」一行，没激活时点一下就能拉起系统激活页。

**v0.9.33** · 空闲息屏 + 唤醒亮屏——机器人一直亮屏耗电快，真机上先量了一遍：`screen_off_timeout=60000`（60 秒明明是有的），但 `stay_on_while_plugged_in=7`、`mStayOn=true`——**「充电时保持唤醒」开着，插着电就永远不会熄屏**，系统超时根本轮不到。所以光在应用里撤掉「保持亮屏」没用，得两条线一起动。①**应用侧**：新增 `ScreenAwake`——录音、播报、触摸、点消息重播时给窗口挂 `FLAG_KEEP_SCREEN_ON`，进入萌眼待机 N 秒后撤掉。灵动模式才有这个行为，普通/大字模式完全不受影响。②**系统侧**：把 `SCREEN_OFF_TIMEOUT` 对齐到设定秒数，并关掉 `stay_on_while_plugged_in`（后者要 `WRITE_SECURE_SETTINGS`，由部署方 adb 授权；拿不到时应用侧仍生效，只是插电时可能不灭）。③**唤醒亮屏**：`onWakeConfirmed` 第一件事就是拿带 `ACQUIRE_CAUSES_WAKEUP` 的唤醒锁（8 秒自动释放）+ `setShowWhenLocked/setTurnScreenOn`，屏幕立刻回来，不会出现「它答应了但屏幕是黑的」。④**设置可调**：设置 → 模式与系统 → 「空闲息屏」，常亮 / 15 秒 / 30 秒 / 1 分钟 / 2 分钟，默认 30 秒。⑤**触摸即算在场**：在 Initial 阶段旁听指针事件，不消费手势，手指一碰就重新计时。


**v0.9.31** · 短句「一顿一顿」+ 话说一半被切——两件事各有硬原因。①**短句卡顿的三层原因**：`[tts] 文件链 Edge 成功` 说明除首句外，每句都是「整段合成成 mp3 → new MediaPlayer → setDataSource → prepare → start」，这台 MTK 上 `prepare` 就要 300~600ms；Edge 每段音频首尾又自带 0.2~0.8 秒静音；再加上「好。」「是的。」这种三五字的句子被单独切成一段去合成。三者叠起来，一句「这是一个好东西」被拆成三段播，听感就是「这，是一个好，东西」。修法：**整段回答共用一条 AudioTrack**——只在一句话开头建一次轨，后续每句解码成 PCM、掐掉首尾静音（首留 60ms 别削字头、尾留 150ms 保自然收尾）直接续写，段间只剩几十毫秒解码耗时，且被 2 秒缓冲完全吃掉；同时碎句不再单独成段（首句 <4 字、后续 <10 字并到下一句），首句逗号切分门槛 8→10 字，后续强制切 34→48 字（34 字常切在定语中间，读出来是半截话）。②**话说一半就被送走**：收段判据原来是死数 1.15 秒，说得慢的人句中一个 1.5 秒的思考停顿就超了，后半句被切成新的一句单独去识别。改成**语速自适应**——记住本句里出现过的最长停顿，收段门槛 = max(基准, 最长停顿×1.7)，上限 2.6 秒；基准同时抬到 1.3 秒，单句上限 10→15 秒。代价是每句结尾多等零点几秒，换来的是不用重说一遍。

## 🔐 自动发版

推送到 `main`（或在 Actions 手动 Run workflow）即自动：构建 release APK（正式签名，密钥存于 GitHub Secrets）→ apksigner 验证 → 发布 Release（说明按 commit 自动生成，自动清理同版本旧构建）。

发新版本只需修改 `app/build.gradle.kts` 的 `versionName`，tag 自动跟随。

> ⚠️ 签名密钥务必备份——丢失后将无法再以同一签名升级应用。
