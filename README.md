## 为什么是旅游宝

「旅游宝」的能力不设话题边界——生活里的事都能问；在旅行场景（路线、玩法、吃饭、交通、天气）上是看家本领。目标不是做"更聪明的行程规划器"，而是做**途中决策的接管器**：系统被动感知你的体力与情境，在你开口之前给出一个可以立刻执行的动作，**你只保留否决权**。

| 设计原则 | 一句话解释 |
|---|---|
| 🚫 零决策 | 不给你一堆选项让你挑，只给一个能立刻照做的动作 |
| 🔢 带数字 | 时间、距离、价格、班次——没有数字的建议不算建议 |
| 🗣️ 语音优先 | 按住说话、松手即问、回答自动朗读，路上不用打字 |
| 💰 免费优先 | 大模型、语音识别、朗读、离线地图全部有免费开源方案 |

## 🧭 两种界面

| | 普通模式 | 大字模式 |
|---|---|---|
| 定位 | 全功能主界面 | 家里老人的默认界面 |
| 字号 | 标准 | 超大字（按钮 56dp/20sp 起） |
| 交互 | 打字 + 语音 + 快捷开关 | 语音优先：按住说话、说完松手就发 |
| 进入 | 未开大字模式时的默认 | 设置里打开后**启动即进**，退出/返回键=退出应用 |

> 模式切换只认设置里的「大字模式」开关；回答风格（简洁/中等/详尽，默认简洁）同样在设置里调。

## 🚀 快速开始

```bash
git clone https://github.com/jingrongx/66.git
# 用 Android Studio（Ladybug 以上）打开，或命令行构建：
./gradlew assembleDebug
```

首次启动 → 「设置」→ 选服务商（默认 DeepSeek）→ 填入 API Key → 测试连接 → 保存。可选：填高德 Key 解锁附近搜索与步行路线；去「离线地图」下载所在省份；填「常用地址（家）」解锁一句话回家；家里有老人打开「大字模式」。

DeepSeek API Key 在 [platform.deepseek.com](https://platform.deepseek.com/api_keys) 申请；高德 Key 在 [lbs.amap.com](https://lbs.amap.com) 申请（**Web 服务**类型）。所有 Key 只保存在本机 DataStore。

## 🗺️ 路线图

- ⬜ **视频通话**（AI 真人般实时视频对话）：真正的全双工视频对话需要实时全模态大模型，按量计费与"能免费就免费"冲突；当前免费替代 = **语音通话 + 拍照提问**，已覆盖"边看边问"的主要场景
- ⬜ 公共信息飞轮（脱敏贡献公共池：需要用户明示授权 + 轻量后端）
- ⬜ 群体情境层（按同行结构/体力档位加权证据）+ 推荐多样性（探索意愿状态变量）
- ⬜ 足迹热力图与多日轨迹管理（当前只叠加最近轨迹）
- ⬜ 完全离线的端侧语音模型（端侧需引入 sherpa-onnx 类原生库 + 模型下载管理）
- ⬜ 交通时刻表类硬信息的专项数据源接入

## 📜 版本历程

**最近动态**

- **v0.8.39** · 用户消息卡加「✏️ 编辑」「🔁 重发」按钮（普通/大字模式）+ 空卡片兜底：①编辑=撤回这条及其后的所有消息，文本与带过的图片回到输入框（图片从落盘文件恢复成附件），改完再发；重发=撤回后原样再问一遍——对坏答案/空卡片最直接的补救；②空卡片兜底：模型偶发把 answer 整个写成连排 null（深度思考退化输出），0.8.36 的清洗把它清成空字符串后空卡片直接摆给了用户——现在清洗后为空时给一句诚实的「这句我没答上来，请再问一次或换个问法」，严格/宽容/纯文本兜底三条路都过
- **v0.8.38** · 修自动更新不自动的竞态：轮询循环里 checkNow 是发射后不管，循环立刻读状态时检查（1-3 秒网络请求）还没回来，release 永远是旧值——**自动下载从未被触发过**，只有手动进更新页点检查才有用，而手动路径也没接自动下载。修复：检查改为循环内同步等待（挂起函数，拿到结果立刻决定下载），手动检查发现新版同样接自动下载；更新说明的 Markdown 井号同步清洗；顺手修了取消下载时误取消空协程的笔误
- **v0.8.37** · 修地图卡「死板不能拖动」——全屏手势全面放开：全屏地图是独立 Dialog 没有列表竞争，但 v0.8.21 的防误滑手势锁照样套着，而 AndroidView 互操作层不把已消费事件喂给地图 View，导致单指拖动/双指缩放全失效（＋/－按钮程序调用所以还有效，用户吐槽「死板得像张图片」）。修复：全屏彻底放开手势，mapsforge 原生拖动/双指缩放生效；内嵌小图改定向锁——横向拖动与双指捏合放行给地图，纵向拖动消费掉保护会话列表不误滚
- **v0.8.36** · 修「深度思考必现 nullnullnull…」：开启深度思考时模型偶尔在 JSON 信封输出完后继续退化吐一串 null，v0.8.24 的「信封外正文捡回」把这些垃圾当正文合并进了回答（旧版静默丢弃所以无害）。三层清洗：信封外捡回前先剥掉 null 串（纯垃圾直接不合并）；回答正文里连排 null（≥3 个）整段清掉（严格/宽容解析与纯文本兜底都过）；流式阶段同步清洗，不让它滚上屏
- **v0.8.35** · 更新全自动流水线 + 最快线路优选：启动即查 + 每 30 分钟静默复查（用户定的节奏）；发现新版本**自动在后台下载**，下好弹「新版本已下载好」点「安装」直接升级，「稍后」本轮进程不再打扰；更新页手动检查与自动流程共用同一条流水线（应用级单例，绝不双下载）；下载/检查线路**并发探测按首包延迟排序**，谁快走谁、失败垫底（gh-proxy/ghfast/直连）；权限缺失引导到系统安装权限页
- **v0.8.34** · 历法按定位时区换算 + 时辰起止时刻 + DeepSeek 看图放开：①传统历法统一按北京时间推算（民俗基准），设备时区不是东八区（人在国外）时额外换算并标注当地时间，北京时间恒定给出；②时辰注入升级为「申时（15:00–17:00），下一个时辰酉时 17:00 起」，问时辰时刻直接可答；③DeepSeek 最新的 flash 模型已支持视觉，图片上限 0→4（带图不再被拦截）
- **v0.8.33** · 农历/节气/节日本地精确推算 + 相册多图：①接入 lunar-java（JitPack，纯本地无网络），每次提问把「公历+农历干支生肖+时辰+节气（精确到秒的交节时刻与倒计时）+节日」注入情境——实测把立冬交节日答成「不是节气日」这类错误根治（2026-11-07 本地推算=立冬 17:52:05 交节，与紫金山天文台数据一致），民俗讲究由模型基于准确日期发挥或搜索；②相册改多选（一次最多 4 张），图片上限按供应商预设区分，超限自动截断并提示；视频暂不支持（OpenAI 兼容端点无标准视频字段，GLM 视频理解走专有接口，base64 视频 payload 也过大）
- **v0.8.32** · 修「我的记忆」点开崩溃：画像总结一次合并十几条事实时全部用同一毫秒的时间戳，而记忆页用 ts 做 LazyColumn 的 key——重复 key 直接崩（随手记页、纠错记录页同款隐患）。三个存储的时间戳生成改为唯一单调递增，设备上已有的重复 ts 数据在加载时自动重排修复并回写
- **v0.8.31** · 长会话滚动摘要（借鉴 Anthropic 公开的 Claude 记忆架构）：历史只带最近 12 条，会话超过 6 轮后最早的对话被静默截掉——「前几轮有上下文、后面跑偏」的又一诱因。借鉴「交互间隙做离线巩固」思路：每轮回答完在后台把窗口外被截掉的对话浓缩成摘要（保留主题/专有名词/关键数字/结论/偏好，≤200 字）缓存，下一轮提问时作为 system 块注入，不阻塞发送；截掉条数变化才重新生成，生成失败静默降级，删会话清缓存
- **v0.8.30** · 纠错记录管理页：设置新增「语音纠错」区——纠正记录可查看（识别稿→你发送的稿+时间）、搜索（实时显示「共 N 条 · 匹配 M 条」）、单条勾选删除/多条删除/清空全部（带确认）；记录来自纠错飞轮，删掉的条目 AI 纠错不再参考
- **v0.8.29** · 纠错飞轮（用户提议落地）：语音稿显示在输入框后，用户手动改完点发送=认可了发送稿——发送时对比「语音稿版本 vs 实际发送稿」，差异成对记入本地（learned_asr_fixes.jsonl，最多 50 条，长度差超一倍的「重写」不记防污染）；纠正记录注入 AI 智能纠错提示词，下次出现相同/相似识别错误直接照改，越用越准；用户改对的发送稿天然进会话语料强化拼音热词层。盲替换碎片规则（如 就是→酒石）刻意不做——会误伤正常句子，纠正只走 AI 上下文路径
- **v0.8.28** · 语音稿 AI 智能纠错上线（两段式）：本地热词是纯机械的拼音全等替换，修不了「90酸伐尼克兰→酒石酸伐尼克兰」这种数字混写——语音稿进输入框后，再由 AI 结合最近对话与记忆画像做一次纠错（专有名词优先采用上文写法），改完自动回填；**纠错期间发送禁用**（普通/大字模式发送按钮置灰+「⏳ 正在智能纠错」提示），杜绝发出去的还是错的；8 秒超时兜底放行（网络差保留本地热词结果）；铁律约束+机械护栏（纠正稿长度必须与原稿基本一致、原文的词基本都还在），宁可不改不可改错，绝不把问题改成回答；只作用于语音入口，手动输入永不触碰；通话模式松手即发不等纠错（模型看得到上下文）

## 🔐 自动发版与签名

- 发新版本：修改 `app/build.gradle.kts` 的 `versionName`，tag 自动跟随
